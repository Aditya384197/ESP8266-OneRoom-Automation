HARDWARE

Relay configuration

Relay names and polarity

Select the correct trigger type separately for every relay module. The fixed output pins are D1, D2, D5 and D6.

Relay 1 · D1 · GPIO5
Relay 2 · D2 · GPIO4
Relay 3 · D5 · GPIO14
Relay 4 · D6 · GPIO12

Active-Low means the relay turns ON when its GPIO output is LOW. Active-High means it turns ON when the output is HIGH.

One direct physical wall switch

The single switch uses NodeMCU D0 / ESP8266 GPIO16. Select which relay it controls. This is a maintained switch: closed to GND = ON; open = OFF. The physical switch has priority over dashboard, timer, weekly schedule and Firebase commands for that relay.

Required wiring: GPIO16/D0 has no usable internal pull-up. Add an external 10kΩ resistor from D0/GPIO16 to 3.3V. Connect the dry-contact switch between D0/GPIO16 and GND. Use 3.3V logic only. Never connect mains voltage to this pin. Keep the existing factory-reset button on D7/GPIO13; do not bridge D7 to the physical switch.

FIREBASE CLOUD

Remote access

Firebase is not configured

Connect this ESP8266 to Firebase Authentication and Realtime Database. The ESP8266 uses a dedicated device-only Authentication account; it never stores the Admin password and never approves users.

The password is used only for the initial sign-in and is not saved. The device stores the Firebase refresh token in LittleFS. ESP8266 flash is not encrypted, so the refresh token is still physically readable from extracted flash.

Authentication and approval model

  1. Create one Admin user in Firebase Authentication and put that exact UID in firebase.database.rules.json. Do not create Admin from the public app.
  2. Create a separate Firebase Authentication email/password user for this ESP8266. In Realtime Database, create deviceAccounts/DEVICE_UID with {"deviceId":"room8266","enabled":true}.
  3. Apply the included database rules. The Android app will register users as pending; only the fixed Admin UID can approve/reject/revoke them and link approved users to devices.
  4. Local AP, physical switch, timer and schedules continue to work without internet. Remote commands are applied as desired ON/OFF states and the actual relay state is published back.
Security: never expose port 80 on the ESP8266 to the public internet. Firebase HTTPS is certificate-verified. Firebase API key is a project identifier; the device refresh token is a secret, but ESP8266 flash is not encrypted.
