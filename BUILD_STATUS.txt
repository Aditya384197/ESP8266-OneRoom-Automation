ESP8266 OneRoom Automation v1.7.2

Source: based on the latest user-supplied GitHub source archive (commit fa1c126b43ec7c045748f3691be74cf94c1a78dd), with requested GPIO and reset changes.
Board: NodeMCU v2 / ESP8266, 4 MB flash, 1 MB LittleFS layout.

Implemented in source:
- Fixed relay outputs: D1/GPIO5, D2/GPIO4, D5/GPIO14, D6/GPIO12.
- One maintained physical switch on D7/GPIO13; internal INPUT_PULLUP; dry-contact switch to GND.
- Physical factory-reset GPIO and button polling have been removed. Local dashboard reset and Admin-only Firebase reset command are supported.
- Physical switch priority enforced against manual API, timer, weekly schedule and Firebase commands.
- A switch-owned relay skips stale saved-state restoration at boot and is initialized from the physical contact.
- Relay names/polarity/switch assignment use a dedicated no-reboot save endpoint.
- Firebase device-only Authentication sign-in and refresh-token flow.
- Verified TLS REST calls, RTDB desired-state commands, acknowledgements and actual-state heartbeat.
- Fixed Admin UID Realtime Database rules template and Firebase setup guide included.

Additional v1.7.2 changes:
- Automation storage migrates v4 to v5 and remaps a prior D0/GPIO16 switch assignment to D7/GPIO13 while preserving relay names, polarity, timers and schedules.
- The dashboard reset API and Firebase Admin-only reset command erase configuration, then re-apply relay OFF levels using factory-default polarity before restart.

Validation performed in this environment:
- Source archive extracted and required source/assets inspected.
- JavaScript syntax checks, Python syntax check, JSON rules parse, certificate PEM parsing and ZIP integrity checks are run before delivery.
- GPIO mapping and Firebase path/rules were reviewed statically.

Not verified here:
- PlatformIO / ESP8266 compile (toolchain is not installed in this environment).
- GitHub Actions build, physical GPIO/switch operation, real Firebase project sign-in or live RTDB behavior.
- Android app (will be a separate next project after firmware build/hardware confirmation).

Important setup notes:
- Select one relay for D7 switch and connect a dry-contact switch to GND; internal INPUT_PULLUP is enabled.
- Set the fixed Admin UID in firebase.database.rules.json and publish the rules.
- Create a separate device Authentication account and deviceAccounts/{uid} record before saving Firebase settings on the ESP8266.
- The ESP8266 refresh token is stored in unencrypted LittleFS. Do not expose its local HTTP server to the public internet.
- Firebase HTTP/TLS on ESP8266 is synchronous and can temporarily delay cooperative loop work.

Flash layout: firmware.bin at 0x00000; littlefs.bin at 0x300000.


v1.7.2 OTA additions:
- Web OTA supports firmware.bin (U_FLASH) and littlefs.bin (U_FS).
- Combined update uploads firmware first, waits for the device to return, then uploads LittleFS.
- LittleFS settings backup/restore uses the dedicated ESP8266 EEPROM sector; config records are CRC-validated.
- This source has not yet been confirmed by a PlatformIO compile or physical OTA test.

First-install note: flash v1.7.2 firmware.bin and littlefs.bin together once by USB/serial to install the new OTA screen. Later updates can be performed from the dashboard in one guided operation.
